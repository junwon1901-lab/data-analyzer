# 입력 표시 및 양수 목표 예측 보완

GitHub 저장소 최상위에서 ZIP 내부 models, ui, docs, tests 폴더를 업로드한다. ZIP 자체나 바깥 폴더는 업로드하지 않는다. 기존 파일과 같은 경로에 덮어쓴다.

앱을 다시 열고 선체 예제 → 그룹별 분리/선형번호 → 목표값 변환: 양수 전용 로그 변환 → 구조 비교 실행 → 선택 구조 적용 → 학습 시작 순서로 실행한다. 기존 학습 결과는 설정이 달라지므로 다시 학습해야 한다.

입력은 소수점 9자리로 표시한다. 로그 방식은 log(y)를 학습 데이터 통계로 표준화해 학습하고, 역표준화 후 exp로 원래 척도로 돌린다. 목표값에 0 또는 음수가 있으면 명확한 오류로 거부한다. 일반 데이터는 기존 일반 표준화를 선택할 수 있다. 유한한 양수 예측만 반환하며 수치 발산은 오류로 알린다. 양수 출력이 정확도나 물리적 타당성 전체를 보장하지 않는다.

로그 방식의 학습 곡선은 표준화한 로그 목표값의 MSE다. epoch는 이 검증 MSE로 선택하며, 구조는 원래 척도의 검증 RMSE로 선택한다. 최종 R²/RMSE/MAE와 선형 기준 모델은 원래 척도에서 평가한다. 테스트 세트는 구조 선택에 사용하지 않는다.

## 실제 실행 (2026-10-13 한국시간)
같은 선체 데이터, 입력 8개, 그룹 분리, 시드 42, relu, 학습률 0.001, 최대 500회.
- 기존 일반 표준화 32,16: 테스트 R² 0.966472, RMSE 9.485945, MAE 5.995285.
- 로그 방식 32,16: 테스트 R² 0.892781, RMSE 16.963370, MAE 10.071379.
- 로그 방식 4종 비교 후 검증 RMSE로 선택된 64,32,16: 테스트 R² 0.925886, RMSE 14.103523, MAE 8.010267.
- Fn=0.1, Rn=9870390, Cp=0.5674, Cb=0.3667, Cw=0.6908, L/B=3.6232, B/T=3.043, LCB/L=-0.023 입력: 기존 -1.458457 → 로그 선택 모델 0.389456.

음수 예측을 피했지만 전체 테스트 오차는 증가했다. 따라서 정확도가 향상됐다고 쓰면 안 된다. 기존 노션 설명서와 실험 수치는 기존 방식 결과이므로, 새 방식으로 제출한다면 설정과 실제 결과를 함께 교체해야 한다. 위 단일 입력은 학습에 포함된 행에 기반한 작동 확인용이며 독립적 정확도 검증이 아니다.

## 검증 범위
모델 자동 테스트 20개 통과(로그 변환 양수 예측, 학습 통계만 사용, 원척도 평가, 0·음수 목표 거부 포함). Python 구문 검사 통과. 현재 실행 환경에 Streamlit이 없어 화면 자동 테스트는 미실행. 배포 후 UI 확인 필요.
